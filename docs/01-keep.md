# 應保留：Haskell 之所以是 Haskell 的東西

這些是語言的靈魂。後繼語言（PureScript、Idris、Roc、Unison、Elm）幾乎都還在繼承它們。

Simon Peyton Jones 後來也強調：Haskell 死守少數幾個簡單想法（純度、類型類、惰性），即使痛苦也不打折。H2O 對惰性的態度是：**能力留下，預設翻轉**。其餘幾條不打折。

## 1. 純度與參照透明

沒有隱式副作用，才能做等式推理、安全重構、可靠並行。這是最不該妥協的一點。

效果系統可以換實作——`IO`、代數效應、能力系統都可以。**「效果必須出現在類型裡」** 這條原則要留。

## 2. 強靜態類型 + 類型推導

Hindley–Milner 風格的推導、參數多型、高階種類（higher-kinded types）是 Haskell 對業界最大的輸出之一。

類型不是只為了「抓錯」，而是用來引導設計、讓非法狀態無法表示（parse, don’t validate）。

Core 層必須保持：多數程式仍可少寫註解。依賴類型會讓推導變弱——那是 Typed 層的代價，不該變成 Core 的預設稅。見 [07-do-not-add.md](07-do-not-add.md)。

## 3. 代數資料型別 + 模式比對

和、積、遞迴型別，配上窮盡檢查，是表達領域模型最乾淨的方式。

GADT、存在型別可以當進階層，但 ADT 本身必須是一等公民。開放和型別（多型變體）是紀錄的對偶，作為**新增**補上，不是取代封閉 ADT。

## 4. 類型類這個抽象

特設多型、約束、依據類型選實作，這套機制本身很強。要改的是階層設計與 orphan / overlapping 的濫用，不是整個概念。

`Functor` → `Applicative` → `Monad` 這條線是對的，應保留並讓定律可檢查。見 [03-redesign.md](03-redesign.md)。

## 5. 不可變為預設、共享結構

持久化資料結構、引用透明，這是函數式能規模化的基礎。可變狀態若存在，必須是效應（或線性資源），不是預設語意。

## 6. 把效果從純計算裡抽出來

不論最後叫 `IO`、`Effect` 還是代數效應，**純核心與邊界必須分開**。這條比「一定要用 Monad transformer」更重要。

Monad 留下當編碼，而非唯一介面。一等效應與處理器見 [04-must-add.md](04-must-add.md)。

## 7. 參數多型帶來的自由定理

`forall a. a -> a` 幾乎只能是 `id`。這種「類型先於實作」的約束能力，是重寫時最不該稀釋的資產。

隱式參數、過寬的 overload、核心子型別都會稀釋這條。它們列在禁止清單裡。

## 惰性：能力，不是預設

惰性求值作為能力值得留：無限結構、需求驅動管線、融合優化（`foldr` / `build`）都靠它。

應改的是「預設全面惰性」，不是禁止惰性。嚴格資料是常態；惰性列表／串流作為明確型別存在。
