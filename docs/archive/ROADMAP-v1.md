# H2O：由零到 V1.0

這是 **V1.0** 的實作路線（已完成），不是再一則宣言。設計取捨見 `docs/`；當下最小切片見 [`docs/core/CORE-0.md`](docs/core/CORE-0.md)。

**V3.1.0 已完成。** Core 1.1 見 [`docs/20-core11.md`](docs/20-core11.md)。不要在本檔繼續加刀。

原則：**先能跑、再像 H2O、最後才凍結。** 每個版本有驗收指令。驗收沒過，不准開下一刀。不准平行開「編譯器架構」「套件生態」「自舉」來逃避當下那一刀。

## V1.0 是什麼

V1.0 是一門**能寫日常 CLI／資料轉換程式**的語言，不是研究展示、也不是 GHC 替代品。

一個沒讀過本倉庫的人，用 README 在 30 分鐘內寫出並跑通第一個程式。語言有一份**凍結的 Core 1 報告**：沒有 pragma，沒有第二套語法。

### 進 V1.0

- **Core 完整**：純、嚴格預設、ADT、`match` 窮盡、HM + HKT、`trait`／`impl`、列紀錄與開放和型別、安全 Prelude（`Text`、`Maybe`、`Result`、`NonEmpty`）
- **效應列在核心**：`{IO}` `{Except[E]}` `{State[S]}`；`handle` 可換測試／正式處理器
- **結構化並發的一階子集**：父作用域結束則子任務取消（不必一次做完遮罩的全部理論）
- **表面**：Python 縮排、`and`／`or`、`|>`；`h2ofmt` 唯一格式
- **工具**：`h2o run`、`h2o build`（出原生可執行檔）、`h2o fmt`、錯誤訊息是產品（黃金測試鎖定）
- **模組**：多檔、`from`／`import`、`pub`／`priv`；套件＝載入本地目錄
- **Typed 可選註解**：`once`（線性）、`total def`。不是預設稅

### 不進 V1.0（看見就停）

| 項目 | 放到 |
|---|---|
| 完整依賴類型、證明助理 | V1.x Typed |
| FFI、WASM、穩定 ABI | V1.x Systems |
| 自訂宏／報價系統 | 類型與階段凍結之後 |
| 完整套件註冊中心 | V1.x |
| 內容定址（Unison） | V2 評估 |
| GHC Haskell 相容 | 永不 |
| 方法鏈、並置呼叫、`$`、自訂中綴 | 永不 |
| 自舉（編譯器用 H2O 寫） | V1.1 目標，**不是** V1.0 閘門 |

自舉會拖死 1.0。V1.0 用宿主語言實作編譯器即可。

**交付：** `docs/` 裡的取捨、語法、可讀性、分層。

## v0.1 — Core-0（完成）

規格：[`docs/core/CORE-0.md`](docs/core/CORE-0.md)。

單檔、樹走訪、Python 原型。`println` 是主機原語，還不是 `{IO}`。

| | |
|---|---|
| **做** | 詞法與縮排、AST、`|>`／`_` 脫糖、HM、嚴格求值、內建 `map`／`filter`／`join`／`println` |
| **不做** | 效應、trait、列多型、多檔、方法鏈 |
| **驗收** | `h2o run examples/core0_hello.h2o` → `active: Ada, Edsger` |
| **診斷** | `users.filter(...)` 報「`.` 不是方法，請用 `|>`」；`if (x):` 報「條件不要括號」 |

實作順序不可打亂：詞法 → 解析 → 脫糖 → 類型 → 求值 → 診斷測資。

---

## v0.2 — 模組與安全 Prelude（完成）

Core-0 能跑之後，先讓程式能拆檔，並把文字／列表的預設做對。仍無效應列。

| | |
|---|---|
| **做** | `from`／`import`、`pub`；`Text` 不是 `[Char]`；`List` 嚴格；`Maybe`／`Result`／`NonEmpty`；`xs[i]` → `Maybe`；comprehension、`fn` 區塊 |
| **不做** | 套件註冊、orphan、效應 |
| **驗收** | 把 `core0_hello` 拆成 `user.h2o` + `main.h2o` 仍跑通；Prelude 測試禁止 `head : List -> a` |

---

## v0.3 — 類型類（完成）

| | |
|---|---|
| **做** | `trait`／`impl`；`Eq`、`Ord`、`Show`；`Functor`（HKT `F[_]`）；實例與類型同模組；orphan 必須寫 `impl orphan` 否則錯誤 |

## v0.4 — 列紀錄與開放和型別

封閉紀錄已在 0.1。這裡補上**列**這個種類。

| | |
|---|---|
| **做** | `{name: Text, ...R}`；`update` 巢狀；開放和型別 `<Click: ..., ...R>`；`.` 只做欄位／模組 |
| **不做** | 頂層選擇器、子型別 |
| **驗收** | `examples/records.h2o` 通過；兩個同名欄位的不同紀錄可並存於同一模組 |

推導失敗時錯誤是「請給這列加註解」，不是 solver 內部狀態。

## v0.5 — 效應列（語言身分）

此前 H2O 仍像「帶類型的 Python」。這一版才分家。

| | |
|---|---|
| **做** | 效應列 `{IO, Except[E], State[S]}`；`handle ... with:`；`println` 收進 `{IO}`；測試處理器（假 IO）不改業務函數 |
| **不做** | 高階效應（區域、遮罩）的完整理論；`forkIO`；惰性 IO |
| **驗收** | `examples/effects.h2o`：同一 `count_line` 接假 IO 得 `Result`，接真 IO 印出；業務檔零 `handle` |

一階 `op` 即可過關。高階 elaboration 放到 0.7。

---

## v0.6 — 從直譯到可執行檔

0.1–0.5 的宿主是 Python 原型，允許醜。0.6 決定**正式編譯器宿主**（候選：Rust、OCaml；用評測：錯誤訊息可控制、出碼簡單、團隊能養）。評測沒寫完不准開後端。

| | |
|---|---|
| **做** | 前端行為與 0.5 黃金測試逐字一致；小型 IR；`h2o build` 出原生可執行檔；尾呼叫與明顯內聯即可 |
| **不做** | GHC 級優化、LLVM 研究、增量編譯當產品 |
| **驗收** | 用 H2O 寫一支 ≥200 行的小工具（讀檔、轉換、寫出），`h2o build` 後不靠直譯器執行 |

Python 原型可留作對照，不再加功能。

## 依賴（什麼不能搶跑）

```
0.1 ──► 0.2 ──► 0.3 ──┐
                      ├──► 0.5 ──► 0.6 ──► 0.7 ──► 0.8 ──► 0.9? ──► 1.0
            0.4 ──────┘
```

- 沒有 0.1，不准做效應「因為比較有趣」。
- 沒有 0.3+0.4，不准做 0.5（列的種類要先穩）。
- 沒有 0.5，不准談自舉、套件、LSP 當主線。
- 0.8 的黃金測試從 0.1 累積；0.8 只是閘門。

## 風險

| 風險 | 處理 |
|---|---|
| 效應 elaboration 過深 | 0.5 只做一階；高階留給 0.7 的 `with`／取消 |
| 列 + HM 推導爆炸 | 失敗就要求註解；禁止無限回溯 |
| 原型與正式編譯器分叉 | 0.6 以 0.5 黃金測試為合約，行為不一致不准切後端 |
| 診斷腐化 | 從 0.1 鎖訊息；內部詞進錯誤＝CI 紅 |
| 新糖偷偷進來 | 每版對照「永不」與該版「不做」；禁用構句進負向測資 |
| 自舉綁架 1.0 | 自舉不是閘門 |
