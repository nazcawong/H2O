# 可讀性：H2O 的表面標準

語義是 Haskell 的（純、類型、等式推理）。**表面怎麼寫，不跟 Haskell 學。**

可讀性不是口味，是噪聲管理。視覺焦點必須留在「資料是什麼、效應是什麼」，而不是括號、符號與兩種寫法之間的選擇。

## 兩個噪聲

1. **語法噪聲**：`{}`、多餘的 `()`、`;`、`&&`、`$`、`>>=`。人眼先碰到符號，才碰到邏輯。
2. **概念噪聲**：同一件事三種寫法；隱式副作用；讀程式時要在腦裡做語法轉換。

Python 把語法噪聲降到日常語言裡最低；Haskell 把概念噪聲（副作用、可變）從核心拿掉，但表面符號反而很重。H2O 要兩邊。

## 四個榜樣，各取一件事

| 來源 | 取 | 不取 |
|---|---|---|
| **Python** | 縮排、英語關鍵字、`if cond:` 無括號、沒有 `;`、沒有區塊 `{}`、長得像偽代碼 | 可變預設、`None` 當空值、部分函數、隱式 IO |
| **Elixir** | `|>` 讓資料自上而下流動；管線是**唯一**的多步轉換寫法 | 可選括號的兩套呼叫、宏文化 |
| **Haskell** | 宣告式含義：描述「是什麼」；純；類型即規格 | `$`、並置、`do`、運算子生態、`::` |
| **Go** | 一件事一種寫法；官方格式化；讀別人的碼沒有適應期 | 刻意去掉泛型／效應那些我們需要的表達力 |

系統層另外對齊 **Zig**（沒有隱式控制流、沒有隱式分配——效應列與線性就是這件事）和 **Odin**（宣告寫成人話，不寫 C 式 `int (*f)(int)`）。

## 偽代碼之王：條件必須長這樣

```
if user_is_active and data_is_ready:
    start()
```

不是：

```
if (user_is_active && data_is_ready) { ... }
```

`and` / `or` / `not` 是關鍵字，不是 `&&` `||` `!`。條件外面沒有括號。區塊靠縮排。這是不可商量的 Core 規則。

## 資料必須長這樣

```
users
    |> filter(_.active)
    |> map(_.name)
    |> join(", ")
```

不是 `map name . filter active $ users`，也不是 `users.filter(...).map(...)`。

- `.` 只表示**欄位**或**模組路徑**（`user.name`、`io.println`）。
- 多步轉換只用 `|>`。
- `x |> f()` 就是 `f(x)`；`x |> f(a)` 就是 `f(x, a)`。
- 單步、就地產生列表，用 Python 式 comprehension：`[x.name for x in users if x.active]`。

兩種列表寫法的分工是固定的，不是風格選項：

| 情況 | 寫法 |
|---|---|
| 一步、元素運算式很短 | `[e for x in xs if p]` |
| 兩步以上、或函數已有名字 | `xs \|> f() \|> g()` |

## 一件事一種寫法（Go）

| 要做的事 | 唯一寫法 | 禁止的第二種 |
|---|---|---|
| 區塊 | 縮排 + `:` | `{}`、`do`、`begin` |
| 布林 | `and` `or` `not` | `&&` `\|\|` `!` |
| 條件 | `if cond:` | `if (cond)` |
| 呼叫 | `f(x, y)`、`f()` | 並置 `f x y`、可選括號 |
| 欄位 | `p.name` | 頂層選擇器、UFCS 方法鏈 |
| 多步資料流 | `|>` | `.map.filter`、`.` 函數合成、`$` |
| 部分套用 | `_` | 自動 curry、運算子 section `(+1)` |
| 效應序列 | 換行 + `=` | `do` / `<-` / `>>=` |
| 空值 | `Maybe` / `None` | `null`、部分函數假裝總是有值 |
| 格式 | `h2ofmt` 唯一 | 對齊風格之爭 |

沒有「個人風格」。沒有第二套呼叫語法。格式化工具像 `gofmt`：不討論，跑過就好。

## 概念噪聲：讀程式時腦中不要轉換

- **沒有隱式 IO。** 函數類型上的 `{IO}` 就是控制流的一部分（Zig：沒有隱藏的控制流）。
- **沒有隱式可變。** `=` 是繫結，不是突變。
- **沒有隱式失敗。** `xs[i]` 是 `Maybe`；`head` 只活在 `NonEmpty`。
- **效應處理器寫在邊界。** 業務函數讀起來像純轉換；`handle ... with:` 才接到世界。

Haskell 的數學可讀性來自這四條，不是來自 `$`。H2O 把這四條留下來，把符號換成英語與縮排。

## 檢驗句

寫下一行之後問：

1. 眼睛先碰到的是名字，還是括號／運算子？
2. 同一件事，語言還允不允許另一種寫法？
3. 有沒有效應沒出現在類型上？

三個都通過，才算 H2O。細節落在 [10-syntax.md](10-syntax.md)。
