## REPL：現在沒有，這一刀也不做

`./h2o` 沒有 `repl` 子命令。入口是 `run`／`check`／`ir`／`dump-bc`／`tokens`／`diagnostics`／`fmt`／`build`。`run` 要整檔、要 `def main`。VM 核沒有 `stdin`／`read_line`。`desugar.h2o` 的 `repl_holes` 是填 `_`，不是互動環境。

所以：**沒有像 GHCi 的東西。** 沒有 `:t`、`:load`、`:reload`、多行輸入、tab 補全、除錯器。

GHCi 能用，是因為推導與環境是一等的。現在做 REPL，只會得到「讀一行、當腳本跑」的 Python 式迴圈，印得出值、說不出類型。那會讓人以為 H2O 是直譯器語言。

若 T4 過了，REPL 可以當**下一刀之後**的刀（建議 R0–R2），仍不開語法：

| 閘門 | 做 | 驗收 |
|---|---|---|
| R0 | C 核 `read_line`；`h2o repl` 讀 stdin | 輸入 `1 + 2` 印 `3` 後繼續等 |
| R1 | 頂層 `def`／`=` 累積環境 | 先定義 `add`，再 `add(1, 2)` |
| R2 | `:t e` 印推導類型；`:load path` | `:t add` 含 `Int`；載入 `examples/bh_hello.h2o` 後能呼叫其中的 def |

**狀態（2026-09-12）：內建類型 + REPL 已綠。** 見 [16-repl.md](16-repl.md)。

R2 不是 GHCi：沒有 `:k`、沒有 breakpoint、沒有 `ans` 活綁定。不要把 R0 叫做 GHCi。
