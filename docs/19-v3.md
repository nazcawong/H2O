# 由 V2.5 到 V3：機器碼，不是解釋器套殼

日期：2026-09-13。Core 1 仍凍結，**不准再開語法**。  
現況：[compare.md](compare.md)。V2.5：[18-v2x.md](18-v2x.md)。Systems 報告：[systems/REPORT.md](systems/REPORT.md)。

V2.5 兌現的是：能養本地 CLI、`once`／`Vect` 擋非法狀態、WASI 裡仍是**同一套 VM**。  
當時 `--native` 是 `--vm` 的別名：`cc` 出來的是帶解釋器的原生行程。N0 之後 `--native` 發 C 函數再 `cc`，是機器碼（仍 tagged `Val`）。

**V3.0.0 已綠。**

---

## V3 是什麼

`h2o build --native examples/count -o count` 產生的可執行檔裡，使用者的 `main`／`nlines` 是機器碼（經 C，或之後經 LLVM）。`otool -tv`／`nm` 看得到這些名字。跑起來輸出與 `h2o run` 相同。

套件**仍然是目錄**。遠端只許把一個目錄拿來放進樹裡。沒有 crates.io、沒有 Hackage、沒有 `]` 註冊中心。

V3 **不是**：GHC NCG、工業 LLVM 優化管道、pip、cargo。

```
V2.5.0 已綠           once／Vect／WASI-VM／有類型 FFI
        │
N0  V2.6               **已綠** --native 發 C 函數，不再只是解釋器+陣列
        │
N1  V2.7               **已綠** 黃金 CLI 的 native 牆鐘低於 `h2o run`
        │
N2  V2.8               **跳過**（N1 已證明 native C 夠用）
        │
P0  V2.9               **已綠** git vendor＝目錄（不是 registry）
        │
V3.0.0                 **已綠** 文件：`--native` 發 C 函數再 cc，是機器碼
```

每一刀有驗收。沒綠不准開下一刀。**不准**用「先接 LLVM」「先做 registry」逃避 N0。

Core 1.1（列多型推導、HKT kind、overlapping solver）是**另一條線**，見文末。本路線是 Systems。不准兩線平行搶跑。

---

## 原則

1. 黃金測試是合約。`--native` 改義＝先改測試再改編譯器。
2. 一件事一種寫法。`--vm` 留下當「解釋器映像」；`--native` 只在真正發函數之後才改義。
3. C 仍是運行時核（`Val`、GC、builtin）。發碼目標可以是 C；那不是「把編譯器改用 C 寫」。
4. 編譯器仍是 H2O（BH）。不准新語法。
5. 套件＝目錄。vendor 只增加目錄，不增加解算器。
6. LLVM 是 N2，不是 N0。沒有 C 發碼當合約，LLVM 會變成無底洞。

## 現況（V2.5.0 出發點，歷史）

| 洞 | V2.5 當天 |
|---|---|
| `--native` | 當時是 `build_vm_path`：`rt.c` + `_h2o_code[]` + `vm_run`。Mach-O 是真的，**程式是解釋出來的** |
| `--target wasm` | 同一套 VM 交叉編譯。已綠，不是本路線的閘門 |
| LLVM | 沒有 |
| `]` | 說明本地目錄；沒有 index |
| 遠端依賴 | 沒有。`import` 只找旁邊的檔／`mod.h2o` |

## 那三句話怎麼做

### 1. 「`--native` 仍不是機器碼」

**做：** 不要再把解釋器鏈進去當 `--native`。

N0 發 **C 函數**：每個 H2O `def` 變成一支 C 函數，參數／回傳仍是 `Val`，builtin／GC 仍用 `rt.c`。`main` 呼叫生成的 `h2o_main`，**不**進入 `vm_interp` 的 opcode `switch`。

這已經是機器碼：`cc` 之後 CPU 跑的是 `nlines` 的加法，不是 `OP_ADD` 解碼。

**驗收：**

```
./h2o build --native examples/count -o /tmp/count
/tmp/count run examples/count examples/count/sample.txt   # 或設計成 argv 吃檔
# 印 count 3
nm /tmp/count | grep nlines
# 有符號。禁止只靠 vm_interp 跑這個程式。
```

`--vm` 保留：仍是今天這套映像。文件寫清兩種後端。在 N0 綠之前，`--native` **繼續**當 `--vm` 別名（誠實）；N0 綠的當日才改義，並改 `./test` 的 `native` 項。

**不做（N0）：** LLVM、寄存器分配研究、去 `Val` 的 boxing、分代 GC。

### 2. 「沒有 LLVM」

**做：** 在 N0 的 C 發碼當合約之後，N2 加一條 `--target llvm`（或 `--native --llvm`）。

同一套語意：仍是嚴格、`Val` 或明確的 unbox 規則、同一套 GC 根。LLVM 只是把「C 當可攜 IR」換成「LLVM IR 當可攜 IR」。

閘門必須是：

- `examples/count` 的 LLVM 映像輸出與 `h2o run` 相同
- 不是「能 clang -S 出一堆 IR 就算綠」
- 沒有 LLVM 的機器，`./test` 的 llvm 項可以因工具鏈缺失而**紅**（不准用假後端當綠，規則與 E2 的 wasm 相同）

**為什麼不放第一刀：** LLVM 會逼出 GC 插件、異常、呼叫慣例、平台三重。沒有「C 函數＝合約」當對照，你無法判斷是後端錯還是語言錯。

**可以跳過 N2。** 若 N1 已證明 native C 夠用，V3.0.0 可以不帶 LLVM。LLVM 不是 V3 的定義特徵；**機器碼**才是。

### 3. 「沒有套件註冊中心」

**語言裡不做。** Core 1：套件＝本地目錄。這不是還沒做，是合約。crates.io／Hackage／PyPI 會逼出版本解算、yank、惡意套件、第二套導入語法。

V3 只許 **P0：把遠端變成目錄**：

```
h2o vendor <git-url> [name]
```

效果：`vendor/name/` 出現，裡面是普通 `.h2o`。之後 `import`／`:load vendor/name/` 與今天載入本地目錄相同。`]` 說明「vendor 是目錄；沒有 registry」。

**驗收：** `./test` 有一個假 git 樹（或 `file://`），vendor 之後 `h2o run` 能呼叫裡面的 `pub def`。沒有網路也能跑（vendor 進樹）。

**不做：** 中央 index、semver 解算、lockfile 產品化、`]` 瀏覽遠端套件、checksum 生態。那些要另開產品，不是 H2O 語言的下一刀。

## N0 — V2.6：發 C 函數

**已完成。** `compiler/emit_nat.h2o`：每個 H2O `def`（與 lambda）是一支 C 函數 `h2o_<name>`／`h2o_lam_N`。`--vm` 仍吐陣列+`vm_run`。

| 做 | 驗收 |
|---|---|
| 每 def 一支 C | `examples/count` 的 `nlines`、`touch`、`main` 在 `.c` 裡是函數，不是 opcode |
| 語意 | `h2o build --native` 跑 `count` 對 `sample.txt` 印 `count 3`（黃金檔） |
| `--vm` 不漂 | 舊映像路徑、`./test` 的 `vm-add`／`wasm` 仍綠 |
| 種子 | `compiler/seed.c` 仍是 **VM 映像**（編譯器自舉不改走 native；那是另一刀） |

**不做：** LLVM、unbox、把 REPL 改 native。

閘門：`./test` 的 `native` 項改成「符號 + 黃金輸出」，不再只是 `grep OP_HALT`。

## N1 — V2.7：有證據的快

**已完成。** `examples/count` 同一份夾檔：`--native` 可執行檔牆鐘中位數低於 `h2o run`（先熱身；允許抖動）。仍是 tagged `Val`，不是 unbox。

| 做 | 驗收 |
|---|---|
| 對照 | `examples/count` 對同一份夾檔，native 牆鐘 **低於** `h2o run`（允許抖動；不准 native 更慢還叫綠） |
| 誠實 | 文件寫：仍是 tagged `Val`，不是 Rust／C 的 unbox 世界 |

**不做：** 基準遊戲、微優化當閘門、為了數字去 GC。

---

## N2 — V2.8：可選 LLVM

**跳過。** N1 已證明 native C 夠用；LLVM 不是 V3 的定義特徵。若之後要做：

- 輸入是 N0 已能發的那套函數級 IR（不要另起一套 H2O）
- `llc`／`clang` 出可執行檔
- 工具鏈寫進 README；沒有 LLVM＝該項紅，不准假裝

**不做：** 當 N0 的替代品先做。

---

## P0 — V2.9：vendor 是目錄

**已完成。** `h2o vendor <git-url> [name]` 把 git 樹拷進 `vendor/<name>/`。之後 `h2o run vendor/name`／`:load vendor/name/` 與本地目錄相同。`]` 說明 vendor，仍寫沒有 registry。N2 已跳過。

| 做 | 驗收 |
|---|---|
| `h2o vendor` | 把一個 git 樹（測試用 `file://`）拷進 `vendor/<name>/` |
| 載入 | `h2o run`／`:load vendor/name/` 與本地目錄相同 |
| `]` | 說明 vendor；仍寫「沒有 registry」 |

**不做：** 註冊中心。

## V3.0.0 — 產品閘門

**已完成。** 版本 **V3.0.0**。compare.md 不再寫「`--native` 不是原生／仍不是機器碼」。

| 做 | 驗收 |
|---|---|
