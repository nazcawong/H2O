# 由現況到 V2.0.0：能開發的路線

日期：2026-09-13。Core 1 仍凍結，**不准再開語法**。  
這是實作路線，不是再一則宣言。現況對照：[compare.md](compare.md)。V1 歷史：[ROADMAP.md](../ROADMAP.md)、[13-next.md](13-next.md)。

V1.0 合約寫的是「能寫日常 CLI／資料轉換」。實作今天能跑示例與自舉，**還不能當開發系統**（無回收、模組是拼檔、Prelude 說謊、無本地套件、`--native` 不是原生）。V2.0.0 把這句話補到工程上站得住。

---

## V2.0.0 是什麼

一個沒讀過本倉庫的人，用 README，在一天內寫出並**長期跑**一個多檔 CLI：讀檔、轉換、寫出。`h2o check` 擋類型錯。記憶體不單調漲死。依賴只有 Prelude 與**本地目錄**。

V2.0.0 **不是**：GHC 替代品、pip／crates.io、LLVM、Koka 級效應列、LSP 產品、證明助理。

```
現況 V1.1 切片     T0–T6、REPL／入門、弱固定點
        │
D0  V1.2           **已綠** 合約對齊（comprehension 脫糖；prelude check／run）
        │
D1  V1.3           **已綠** 模組是邊界；套件＝本地目錄
        │
D2  V1.4           **已綠** 能用的 Prelude／CLI IO
        │
D3  V1.5           **已綠** GC（標記－清除）
        │
D4  V2.0.0         **已綠** 黃金工具 + 文件誠實 + ./test
```

每一刀有驗收指令。沒綠不准開下一刀。不准平行開「先做 LLVM」「先做 registry」「先換 Rust」來逃避當下那一刀。

---

## 原則

1. 黃金測試是合約。行為一變，先改測試再改編譯器。
2. 一件事一種寫法。新能力必須減少特例。
3. Core 1 已寫、實作沒做的，是**兌現**，不是開新語法（例如 comprehension 二選一）。
4. C 只加運行時核（GC 在 `rt.c`）。編譯器仍是 H2O（BH 子集）。
5. 套件在 V2.0.0 ＝載入本地目錄。**不做註冊中心。**
6. `--native` 在 V2.0.0 仍是同一套 VM。文件必須繼續這麼寫。真機器碼是 V2.x Systems，不是本路線的閘門。

## 現況（出發點）

已綠：V1.0.1 黃金檔、自舉弱固定點、日常不靠 Python、T0–T6（HM 子集、`A: Eq`、兩份 `Functor` impl）、REPL 與 `docs/learn` 0–9。

仍擋「能開發」的：

| 洞 | 今天 |
|---|---|
| 記憶體 | 無 GC，一直 `malloc` |
| 模組 | `import` 拼檔；`pub` 不擋 |
| 套件 | `]` 誠實空殼 |
| Prelude | `examples/prelude.h2o` 在 D0 起 check／run 綠 |
| IO | 讀寫檔、argv、shell；沒有 stderr／exit 碼產品化 |
| 後端 | tagged VM 包進 C |
| 速查 | `[e for x in xs if p]` 已脫糖（D0） |

## D0 — V1.2：合約對齊

**已完成。** 速查、教學、parser 只許一套故事。沒過 D0，不准談模組。

| 做 | 驗收 |
|---|---|
| `[e for x in xs if p]` | **已兌現：** 脫糖成 `filter`＋`map`（Core 1 已寫的表面） |
| `examples/prelude.h2o` | `h2o check` 與 `h2o run` 綠（`prelude-ok`） |
| 入門 | `docs/learn/4.txt` 教 comprehension；速查與 parser 同一套故事 |

**不做：** GC、新語法、假套件庫、把 `==` 改成全域 `Eq.eq`。

閘門：

```
./h2o check examples/prelude.h2o
./test
```

---

## D1 — V1.3：模組是邊界，套件是目錄

**已完成。** 檔裡出現 `pub` 之後，未標的名字對匯入方是私有。沒有任何 `pub` 的檔（編譯器、單檔腳本）仍全部匯出。`import foo` 先試 `foo.h2o`，否則 `foo/mod.h2o`。`h2o run dir/` 載入 `dir/main.h2o`。`]` 仍**沒有**註冊中心。

| 做 | 驗收 |
|---|---|
| `pub`／未匯出 | 另一檔呼叫私有 `def`＝編譯失敗，訊息點名 |
| 本地目錄 | `h2o run`／`:load` 能從目錄當套件載入公開介面 |
| REPL `]` | 說明「本地目錄，沒有 registry」；給出載入一個目錄的指令，不做假 index |

測資：`tests/cases/priv_hidden.h2o`（或兩檔）進 `./test`。黃金小工具改為至少兩檔 + 一個本地目錄。

**不做：** 遠端 registry、版本解算、lockfile 產品化、orphan 審計 UI。

閘門：

```
./h2o check tests/cases/priv_hidden.h2o   # 紅，含私有名
./test
```

## D2 — V1.4：能用的 Prelude 與 CLI IO

**已完成。** `eprint`／`exit` 是 `{IO}`。黃金工具：`tests/pkg/wc`（`lib.h2o` + `main.h2o`，argv／讀檔／stderr／exit）。

| 做 | 驗收 |
|---|---|
| 列表／文字／Maybe／Result | 只靠 `prelude/` 能寫過濾、join、讀檔、寫檔 |
| CLI | `argv`、stdout、**stderr**、**exit 碼** 有閘門 |
| `{IO}` | 純函數裡這些仍是類型錯誤（舊黃金檔不漂） |

**不做：** HTTP、資料庫、時間輪、完整 POSIX、加厚 Except 框架。

閘門：多檔工具只用 Prelude + 本地目錄，`h2o check` 綠、`h2o run` 對一份夾檔給出固定輸出（黃金檔）。

```
./test
```

## D3 — V1.5：GC（硬閘門）

**已完成。** `rt.c` 標記－清除：List／紀錄／建構子／文字／閉包陣列。`gc()` 回傳存活物件數。分配超過閾值會收；測試用 `gc()` 鎖定活物件不隨 churn 單調增加。

| 做 | 驗收 |
|---|---|
| 最小標記－清除（或同等：能回收不可達 `Val`） | 寫在 `compiler/rt.c`；編譯器不在 H2O 裡重寫分配器 |
| 分配迴圈 | 反覆建大列表再丟掉，**多輪 RSS 不單調爬死**（`./test` 有閘，允許抖動，不允許每輪只增不減） |
| REPL | 重複求值 `range(10000)` 類表達式，行程不爆 |

**不做：** 分代研究、壓縮、並行 GC、所有權／借用檢查器（那是 Typed，V2.x）、把泄漏說成「arena 就夠」（`h2o run` 一次結束不是 REPL）。

閘門：新測資進 `./test`；`h2o check compiler/h2oc.h2o` 仍綠；種子更新。

## 明確不進 V2.0.0

| 不做 | 放到 |
|---|---|
| 套件註冊中心、遠端解算 | V2.x 或永不（Core 1 套件＝目錄） |
| LLVM／真機器碼、真 Wasm 後端 | V2.x Systems |
| 穩定 FFI ABI | V2.x Systems（演示 `ffi_call` 可留） |
| Koka 級列推導、overlapping solver、HKT kind 推滿 | Core 1.1（V2.5 之後）；不是 E0 |
| `h2o fmt` AST 重印成 gofmt | 加分，不是閘門；仍須誠實「只清空白」除非另開刀 |
| LSP、tab 補全、`ans` | 編輯器；不是 V2.0.0 |
| 用完整表面語法重寫編譯器（編譯器仍 BH） | 不當閘門 |
| GHC 相容、方法鏈、`$`、pragma | 永不 |
| 完整依賴類型、證明助理 | Typed，更後 |

Typed 1／Systems 1 的閘門在 [18-v2x.md](18-v2x.md)（E0 `once` 起）。沒有 GC 與模組邊界時不准開那些線——現在已有。

## 和三門能開發語言的關係（V2.0.0 過完之後）

| | V2.0.0 仍比不過 | V2.0.0 追平的窄帶 |
|---|---|---|
| GHC | 生態、優化、惰性、工業 HM | 嚴格小工具；表面更安靜 |
| Python | PyPI、電池、處處能用 | 本機 CLI 資料轉換；有類型擋錯 |
| Rust | 所有權、LLVM、cargo | 不相近；V2.0.0 不宣稱系統安全 |

過完 V2.0.0，H2O 是 **能養本地工具的嚴格腳本語言**（有 GC 的 tagged VM），仍不是工業編譯器。
