# 語言核心應新增的六件事

上一層談的是「留什麼、丟什麼」。若重寫，真正決定成敗的往往是**必須新增、且不能再用擴充模擬的能力**。

現有 GHC 已在實驗其中一部分（線性型別、Dependent Haskell 路線圖），但重寫時應把它們做成語言核心，而不是再疊一層 pragma。

原則：新增的東西必須減少擴充數量，而不是再製造一批擴充。

## 1. 一等代數效應與處理器

Monad 與 transformer 堆疊能編碼效應，但把「宣告效應」和「解釋效應」綁死在類型建構子裡。H2O 採 Koka／OCaml 5／Unison abilities 那條路：運算標一列效應，處理器在邊界解釋。

應具備：

- 效應列（effect row）：`a -> {IO, State s, Except e} b`
- 高階效應（資源、區域、遮罩）有模組化 elaboration，而不是只支援一階 `op`
- 同一段業務邏輯可換測試／正式處理器，不必改核心
- `IO` 只是眾多處理器之一，不是萬用垃圾桶

這比「再做一套更好的 MTL」重要。Bluefin、Polysemy、`effectful` 已證明需求存在；它們不該永遠是函式庫層的妥協。

優先序第一。直接消滅最常見的架構痛。

## 2. 一等紀錄、列多型、開放和型別

丟掉經典 record 之後，要補上的是完整替代方案，而不是 `OverloadedRecordDot` 這類補丁。

- 匿名紀錄：`{ name : Text, age : Int }`
- 列多型：可擴充、可限制、欄位順序無關
- 巢狀更新與投影為核心語法
- 開放變體／多型變體（對偶於列）：可擴充的和型別，不必先封死所有建構子

PureScript 已證明：紀錄問題不是「語法糖不夠」，是缺少**列**這個種類。

優先序第二。直接消滅最常見的日常痛。

## 3. 線性／仿射型別成為可用的資源系統

GHC 的 `LinearTypes` 仍標實驗，限制多、錯誤訊息差、與模式／紀錄／TH 互動不完整。H2O 把「恰好用一次／最多用一次」做成資源安全的預設工具，而不是研究功能。

具體用途：檔案控制代碼、緩衝區、唯一所有權、協議狀態機、避免雙重釋放。

目標不是複製 Rust 的借用檢查器，而是：**純函數式語言裡，資源生命週期也能出現在類型上**。與效應系統搭配時，作用域型資源（bracket、with-file）可以是線性處理器，而不是慣例。

所有權＋借用是線性之上的學科，不另做核心原語。見 [06-optional.md](06-optional.md)。

## 4. 實用的依賴類型（不必一次做成 Agda）

不應再靠 singleton、defunctionalized type family 模擬「值出現在類型裡」。要的是依賴量化與依賴模式比對，讓長度索引向量、正確協定、編譯期不變式成為普通寫法。

務實分層：

| 層 | 內容 |
|---|---|
| **必備（Typed）** | 索引族、可視 `forall`、項可提升為類型的穩定子集、依賴模式比對 |
| **可選** | 完整證明、總性、等式推理模式 |
| **不要** | 用三十個擴充假裝已經有依賴類型 |

推導會變弱，註解會變多——這是代價，應誠實接受，並把診斷做成一等公民。Idris 已示範：依賴類型可以是通用語言，而不只是證明助理。

**不要**預設依賴類型全開：會失去 Haskell 最大優勢之一——多數程式仍可少寫註解。

## 5. 可選的總性檢查

部分函數不該只從 Prelude 趕走，還應能在模組或函數層宣告「此定義必須涵蓋所有情況且終止」。

Idris 的 totality checker 是對的方向：預設不強迫全語言總性（以免綁死 I/O 與協作），但核心演算法與資料轉換可以要求總性。

## 6. 結構化並發與取消

`forkIO` + `MVar` + 例外是 1990 年代模型。H2O 內建：

- 結構化並發（父作用域結束則子任務結束）
- 取消與遮罩是效應，不是全域 IO 例外
- 確定性的資源清理與線性／效應系統對齊
- 串流作為標準效應，而不是四套不相容函式庫（pipes／conduit／streaming／streamly）

## 這六件如何對齊分層

| 能力 | 層 | 備註 |
|---|---|---|
| 效應列 + 處理器 | Core | 沒有它，日常架構仍痛 |
| 列紀錄 + 開放和型別 | Core | 沒有它，日常資料仍痛 |
| 嚴格預設、`Text`、安全 Prelude | Core | 見 [02-discard.md](02-discard.md) |
| 線性／仿射 | Typed | 資源的類型 |
| 依賴子集 + 總性註解 | Typed | 不變式的類型 |
| 結構化並發 | Core 效應 + Systems 執行 | 取消是效應；排程是後端 |
