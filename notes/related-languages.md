# 已付學費的設計筆記

重寫時，這些不是對手。**實作現況對照**（今天 `./h2o` 比得過／比不過誰）見 [`docs/compare.md`](../docs/compare.md)。

| 語言 | 已示範的部分 | H2O 怎麼用 |
|---|---|---|
| PureScript | 嚴格、列型別、較清楚的 Effect | 列紀錄與開放和型別的日常性；嚴格預設 |
| Idris 2 | 依賴類型、可選惰性、總性 | Typed 層的務實分層；總性不是全語言強制 |
| Unison | 內容定址、代數效應（abilities） | 效應列思想；內容定址作編譯／套件加分項 |
| Roc | 嚴格、平台邊界 | 純核心與平台／處理器邊界 |
| Elm | 簡化的邊界、友善診斷 | 診斷以程式設計師為中心；不照搬 Elm 的表達力上限 |
| Python | 縮排、英語關鍵字、偽代碼外表 | 表面的噪聲下限；不取可變與隱式 IO |
| Elixir | `|>` 資料流 | 多步轉換的唯一寫法；不取可選括號與宏 |
| Go | 一種寫法、gofmt | `h2ofmt`；不刻意砍掉我們需要的類型表達力 |
| Zig | 沒有隱式控制流／分配 | 效應列與線性；不把系統語法當 Core 表面 |
| Koka | 效應列、處理器、推論 | Core 效應系統的主要參考 |
| OCaml 5 | 效應處理器進入主語言 | 「效應不是函式庫妥協」的存在證明 |
| GHC | 純度、類型類、HKT、rewrite rules、實驗中的線性與 Dependent Haskell | 靈魂與優化思想留下；擴充文化與預設不留下 |
| Clean | 介面／實作分離檔 | 模組封裝參考，不必然照搬檔案佈局 |
| Bluefin / Polysemy / effectful | 社群確實需要可組合效應 | 需求證據；不該永遠停在函式庫層 |

## 調查對齊（2025 State of Haskell → 2026 整理）

反覆出現、且 H2O 直接處理的痛點：

- `String`＝`[Char]`
- 經典紀錄
- 預設惰性
- Prelude 部分函數
- 擴充爆炸

H2O 的四件優先序就是這張清單加上效應——調查裡的架構痛，在實務上通常以 MTL／transformer 堆疊出現。
